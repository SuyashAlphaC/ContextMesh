# Three-minute ContextMesh demo

## Opening: payments need context

“Freelancers receive one client payment, but owe money to several collaborators. A payment API knows amounts and recipients; it does not know the agreement. ContextMesh remembers the relationships, explains the split and asks before paying.”

## 1. Create a plan

Open Overview. Choose GreenCart and use:

> When GreenCart pays, give Maya 60%, Arjun 25%, reserve 10% for taxes and 5% for expenses.

Create the plan. Show the exact $2,000 allocation and its evidence: project, funding state, graph context and approval requirement. Note the deterministic parser when no AI key is supplied.

## 2. Show the funding gate

The plan waits for payment. In demo mode, select Simulate payment and clearly state that no money moved. In connected Sandbox mode, complete a real Sandbox checkout and confirm capture.

## 3. Approve and execute

Review the collaborator identities, allocations and risks. Approve explicitly, then execute. Explain that reserves stay in the ledger; only collaborator allocations become payouts. When connected, show the actual Sandbox batch ID and reconciliation status, plus the Render chained task run if deployed. Never call a pending payout completed.

## 4. Explain why the graph matters

Open Context graph and inspect the project, invoice, plan and recipient nodes. Show the audit trail. Graph context grounds the plan while the server independently enforces financial rules. Changing an account makes an old approval unsafe; the account-version check prevents that payout.

## 5. Sponsor integration payoff

Open Analytics studio. Show live Approval queue and Reserve ledger widgets, then save the dashboard. With a licensed, AI-connected setup, ask the Studio agent to compare project revenue or highlight payment risks. Its tools can change charts, not approve payments.

## Close

“ContextMesh is a financial context layer between human agreements and PayPal execution: explainable plans, verified funding, bounded automation and explicit control.”

## Honest checklist before recording

- Start with a project that has no active plan; completed payouts are deliberately not resettable from the UI.
- Keep demo/Sandbox labeling visible.
- Verify real provider connections before showcasing them as live.
- Obtain required AG Studio license/trial and show evaluation notices honestly if absent.
- Do not expose tokens, recipient private data or provider credentials on screen.
- Avoid claiming hackathon criterion weights, prize eligibility or production readiness without current official confirmation.
